# Local RAG Workshop

A beginner-friendly local Retrieval-Augmented Generation (RAG) application for a student workshop. It lets you upload a PDF or DOCX file, extract text, split it into meaningful chunks, generate embeddings locally, retrieve the most relevant context, and then ask a local Ollama model for a grounded answer.

## Why this project exists

This project is designed to teach the core ideas behind RAG in a practical way:

Document
→ Extract
→ Chunk
→ Embed
→ Compare
→ Retrieve
→ Context
→ LLM
→ Answer

The key idea is that the model does not automatically know the uploaded document. First, the application retrieves the relevant document text. Then that retrieved context is given to the local LLM so it can answer using grounded evidence instead of guessing.

## What is included

- PDF and DOCX upload support
- Local text extraction using PyMuPDF and python-docx
- Light text cleaning and chunking
- Local embedding generation with Sentence Transformers
- Cosine similarity retrieval in NumPy
- Local model detection and selection using Ollama
- Qwen-first, Llama fallback behavior
- Streamlit-based UI for workshop demonstration
- Grounded prompt construction for local generation
- Test suite covering the main pipeline stages

## Setup

1. Create a virtual environment:
   python -m venv .venv
   .venv\Scripts\activate

2. Install dependencies:
   python -m pip install -r requirements.txt

3. Start Ollama locally:
   ollama serve

4. Install a local model, for example:
   ollama pull qwen2.5
   or
   ollama pull llama3.2

5. Start the app:
   streamlit run app.py

## Ollama model selection policy

The app checks the locally installed Ollama models at runtime:

1. Prefer Qwen if a Qwen model is installed.
2. Otherwise use the first available Llama model.
3. If neither is installed, show a friendly setup message instead of crashing.

This makes the workshop more resilient without requiring paid APIs or keys.

## Workshop demo flow

1. Upload a syllabus, policy, or notes document.
2. Review the extracted text and chunk count.
3. Ask a question such as: "What are the eligibility requirements?"
4. Inspect the retrieved chunk cards and similarity scores.
5. Observe the grounded answer generated by the local model.
6. Note when no relevant chunk matches the question and the system responds transparently.

## Technical notes

### Document extraction

PDF and DOCX files are processed locally. The app extracts readable text and keeps the content lightweight enough for student laptops.

### Text cleaning

The cleaner removes repeated whitespace and broken formatting without stripping away the meaning of the source text.

### Chunking

Long content is split into overlapping chunks to balance retrieval quality and speed. This helps the system focus on the most relevant sections when answering questions.

### Embeddings

Embeddings represent the meaning of text in a vector space. Local sentence-transformers models make the workshop accessible without external APIs.

### Cosine similarity

Cosine similarity measures how closely the query vector points in the same direction as the document chunk vectors. It is a lightweight, intuitive way to rank the most relevant results.

### Retrieval

Only the highest-scoring chunks are sent as context to the LLM. This separates retrieval from generation and reduces the chance of a model answering from unrelated content.

### Grounded generation

The LLM receives only the retrieved context plus the question. It is told not to invent facts and to say when the answer is not present in the uploaded document.

## Troubleshooting

- If Ollama is not running, run `ollama serve`.
- If no Qwen or Llama model is available, run `ollama pull qwen2.5` or `ollama pull llama3.2`.
- If a PDF has no extractable text, the app will display a friendly error instead of crashing.
- If a document is empty, the app shows a clear message.
- If retrieval finds nothing, the app asks the user to ask a question related to the document.

## Important note for students

RAG is not the same as uploading a file and asking the model to read it magically. The system first retrieves the most relevant document sections, then it supplies that context to the local model for a grounded answer.
